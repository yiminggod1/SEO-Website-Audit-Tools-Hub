Performance optimization is an investigation problem. A good workflow starts with a fresh measurement, identifies the largest contributors to delay, changes one meaningful cause, and measures again.

01

Start with both device classes

Mobile and desktop can have different bottlenecks. A layout or script that seems fine on a fast desktop can behave very differently under constrained mobile conditions.

02

Prioritize evidence

Look for large resources, excessive JavaScript work, render-blocking resources, slow server response and layout instability before making broad framework changes.

03

Separate score from work

A performance score is useful as a summary, but the opportunity list tells you what to change. Focus on changes that materially improve the page rather than chasing a perfect number.

04

Use field data when available

Lab diagnostics explain possible causes. Real-user data helps you understand what visitors actually experience over time.
