Understand the browser protections your HTML cannot show you.

HOW IT WORKS

Use the tool as a diagnostic, not a magic score.

Results are deliberately explained so you can decide what to change and what not to change.

01

Know the response layer

Headers such as Content-Security-Policy and Strict-Transport-Security are delivered by the server, not ordinary HTML.

02

Review the policy

Understand what a header is intended to protect before copying a configuration from another site.

03

Validate safely

Test your production response and monitor changes. Security settings can break assets or integrations when applied blindly.

SEARCH INTENT

Security headers are server configuration.

A static GitHub Pages front end can explain and prepare the checks, but it should not claim to see remote response headers without an actual HTTP request path.

This page keeps that distinction explicit so users know when they need a production-side checker.
